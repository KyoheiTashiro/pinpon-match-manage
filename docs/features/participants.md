ルート: `/#/t/:tournamentId/participants`（HashRouter・参加者タブ）— 大会に参加する選手の登録・編集・削除を行う画面。

## 画面構成

大会レイアウト（`TournamentLayout`）内のタブとして表示される。
`/#/t/:tournamentId` にアクセスすると `/#/t/:tournamentId/participants` へ自動リダイレクトされる（`App.tsx` の index ルートが `participants` へ `Navigate`）。

---

## 機能

### 見出し

「参加者」と表示する。参加者が1人以上いる場合は「参加者（N人）」と人数を括弧内に付記する。

---

### 参加者追加

見出し直下にインライン追加フォームを常時表示する。

| 項目 | UI | 備考 |
|------|----|------|
| 名前 | テキスト入力（プレースホルダ: `名前`、aria-label: `参加者名`） | — |
| 追加ボタン | 「追加」（`BigButton` デフォルトvariant） | フォームが invalid の間は disabled |

#### バリデーション（`schema.ts` zod 定義）

| フィールド | ルール | エラーメッセージ |
|-----------|--------|----------------|
| 名前 | 必須・10文字以内（trim後） | 空: 「名前を入力してください」、超過: 「名前は10文字以内で入力してください」 |

- エラーメッセージは入力欄の下（フォームの `basis-full` 行）に赤字で表示する。
- 追加成功後はフォームをリセットする（画面は遷移しない）。
- 所属フィールドはUI上に存在しない（型定義 `Participant.affiliation` はストア層の任意フィールドだが、現在の画面では入力・表示ともに行わない）。

---

### 参加者一覧

- 参加者が0人の場合は「まだ参加者がいません。」を表示する。
- 参加者が1人以上の場合はリスト表示する。
- 表示順は `tournament.participantIds` 配列の順序（追加順）に従う。

各行の表示:

```
[名前（太字・truncate）]  [編集]  [削除]
```

---

### 参加者編集

「編集」ボタンを押すと、その行がインライン編集フォームに切替わる。

| 項目 | UI |
|------|----|
| 名前入力 | `aria-label="参加者名を編集"` のテキスト入力（現在の名前を初期値として設定） |
| 保存ボタン | 「保存」（`BigButton` primary, size sm）― フォームが invalid の間は disabled |
| キャンセルボタン | 「やめる」（`BigButton` secondary, size sm） |

- バリデーション仕様は追加フォームと同じ（名前: 必須・10文字以内）。
- エラーメッセージはフォーム下部に赤字で表示する。
- 「やめる」を押すと編集をキャンセルして元の表示行に戻る（名前は変更されない）。
- 「保存」を押すと `updateParticipant` を呼び名前を更新する（名前は trim して保存）。
- 同時に編集できる行は1行のみ（`editingId` ステートで管理）。

---

### 参加者削除

「削除」ボタンを押すと確認ダイアログを表示する。

- ダイアログタイトル: 「参加者を削除」
- ダイアログメッセージ: 「この参加者と関連する試合を削除します。よろしいですか?」
- 確認ボタン: 「削除する」（destructive）
- キャンセルボタン: 「やめる」
- 確認を押すと `removeParticipant` を呼び、対象参加者と関連する試合が同時に削除される。

---

## データ仕様

- 参加者データは `participants` ストア（`Record<string, Participant>`）に格納される。
- 大会との紐付けは `tournament.participantIds`（追加順の配列）で管理する。
- ダブルス大会でも参加者は個人単位で登録する。ペア指定は対戦入力時に行う。
